# 부산 웨딩박람회 현장점검 도구 · 사용 매뉴얼

박람회 현장에서 업체 견적·답변을 기록하고, **사업자등록 상태를 즉시 조회**하고, 데이터를
**GitHub 정합성 원장 → 구글 시트**로 축적하며, **분석·보고서**와 **상견례 예산표 자동 반영**까지
하나로 잇는 도구. 모바일 브라우저 우선, 외부 라이브러리 0, 오프라인에서도 핵심 기능 동작.

> ⚠️ 이 도구는 **자료 수집·비교용**입니다. 현장에서 계약·서명·계약금 결제를 하지 않습니다. 법률 자문이 아닙니다.

## 📖 사용 설명서

### 1. 입력 폼 — 현장 기록
- **업체 추가/삭제**: 하단 `＋ 업체 추가` 또는 우측 하단 버튼. 카드 맨 아래 `이 업체 카드 삭제`(확인 후).
- **유형 선택**: 예식장 / 스드메·드메 / 본식스냅·DVD / 예복·한복·예물 / 신혼여행 / 기타. 유형별 확인 질문이 자동 표시됩니다.
- **사업자등록번호 조회**: 번호 10자리 입력 후 `조회` → 계속사업자/휴업/폐업·과세유형 즉시 확인.
- **질문 체크·답변 메모**: 공통 7문항 + 유형별 문항. 각 문항은 체크와 답변 메모(자동 확장)를 함께 기록.
- **위험 신호**: 하나라도 체크되면 카드 요약줄에 `위험 N` 배지(3개 이상 빨강)로 후보 순위 하향을 표시.
- **예식장 계산기**: 대관료·1인식대·보증인원 입력 시 `최소 지출 = 대관료 + 1인식대 × 보증인원` 자동 계산.
- **견적서 사진 첨부**: 카드 하단 `＋ 사진`. 촬영/선택 시 자동 축소·압축해 기기에 저장(분쟁 증거용).
- **자동 저장**: 입력 0.8초 후 자동 저장. 상단에 저장 상태·경고가 뜹니다. **오프라인에서도 기기에 저장**되고, 온라인 복귀 시 시트로 자동 전송(지수 백오프 재시도).

### 2. 예식장 견적 비교 (`예식장 견적 비교` 버튼)
업체마다 보증 단위가 달라 총액만으론 비교가 어렵습니다. 3가지 표로 봅니다.
- **정규화 랭킹**: 상단에서 인원(120/130/150/200) 선택 → `적용인원 = max(선택, 업체 최소보증)` 기준 최소지출 오름차순. 최저가 강조, `↑`는 최소보증이 선택 인원보다 커서 못 내리는(강제 상향) 경우.
- **보증 구간별 총액**: 120 / 150 / 200명 각 총액을 한 번에 비교.
- **인당 단가 — 보증 구간별**: `150명 미만 / 150~200 미만 / 200명 이상` 구간으로 나눠 **인당 단가 = 1인식대 + 대관료 ÷ 보증인원**. 보증 단위가 달라도 1인 기준으로 공정 비교(총액이 커도 인원이 많으면 인당은 쌀 수 있음).

### 3. 분석·보고서 (`분석·보고서 열기` / `…?page=report`)
축적된 시트 데이터를 실시간 집계합니다.
- **KPI**: 총 업체 / 예식장 / 계속사업자 확인 / 위험신호 업체 수
- **유형별 분포**, **예식장 최소지출 비교**(최저가 강조), **위험신호 현황**, **사업자등록 검증 현황**, **업체 목록**
- **보고서 인쇄·PDF**: `보고서 인쇄 · PDF` → 브라우저 인쇄로 A4 보고서 저장(제출용). 원본 데이터는 구글 시트에 보관.

### 4. 상견례 예산표 자동 반영 (`상견례_협의_체크리스트.html`)
입력 폼에 저장된 **예식장 실측 견적**이 상견례 예산표의 `예식장(대관+식대)` 행·`총지출`·`실질 순부담`에
자동 반영됩니다(원 견적과의 차액만 반영, 재실행해도 동일). 데이터는 GitHub 원장에서 **온라인으로** 읽어
다른 기기에서도 최신값이 반영되고, 오프라인이면 이 기기 로컬값으로 대체됩니다.

### 5. 기록 내보내기
하단 `기록 내보내기` → 전체 기록을 텍스트/표(TSV) 형식으로 복사. 시트 연동이 없어도 백업·공유 가능.

## 🔄 데이터 흐름

```
[입력 폼] --submit--> [Apps Script]
                         │ ① 정합성 검증(스키마·규칙)  ← 구글 시트가 아니라 여기서 검증
                         │ ② GitHub 커밋(data/fair-data.json = 버전관리 원장)
                         │ ③ 통과분만 구글 시트 upsert(중복 방지)
                         ▼
                    [구글 시트]  ──집계──▶ [분석·보고서]
                         
[GitHub 원장 raw JSON] ──온라인 읽기──▶ [상견례 예산표]  (오프라인 시 로컬 폴백)
```

- **전송 방식 자동 전환**: Apps Script가 페이지를 서빙하면 `google.script.run`(링크 하나로 끝), 파일/정적 호스팅이면 `fetch`(엔드포인트 입력). 같은 파일이 양쪽에서 동작.
- **사업자 조회**: 국세청 상태조회 API를 Apps Script가 중계(키 은닉·CORS 회피).

## 🚀 배포 (PC에서 1회)

요약 — 자세한 절차는 **[`배포_가이드.md`](./배포_가이드.md)** 참고.
1. 구글 스프레드시트 → 확장 프로그램 › Apps Script
2. **`Code.gs` 하나만** 붙여넣기(=`구글시트_연동_AppsScript.gs`). **화면 HTML은 GitHub에서 자동 서빙**되므로 별도 HTML 파일 불필요.
3. ⚙ 프로젝트 설정 › 스크립트 속성: `GITHUB_TOKEN`(Contents R/W), `NTS_API_KEY`(선택)
4. 배포 › 웹 앱(실행: 나 / 액세스: 모든 사용자) → `…/exec` 링크 확보
5. **HTML 수정은 재배포 불필요**(GitHub push → 최대 30초 내 자동 반영, 즉시는 `?refresh=1`). `Code.gs`를 바꿀 때만 "새 버전"으로 재배포.

> 브랜치를 기본 브랜치로 병합하면 `Code.gs`의 `GITHUB_BRANCH`와 예산표의 `FEED_URL` 브랜치명을 갱신하세요.

## 🛠 문제 해결
- **저장은 되는데 GitHub 커밋 안 됨**: `GITHUB_TOKEN` 미설정/권한 부족 또는 `GITHUB_BRANCH` 불일치. 토큰 없으면 시트 저장만 되고 원장은 건너뜀(정상).
- **사업자 조회 실패**: `NTS_API_KEY` 미설정 또는 Encoding 키 사용(반드시 **Decoding** 키).
- **폼/보고서 안 열림**: `Code.gs`의 `RAW_BASE` 브랜치가 맞는지, GitHub 접근 가능한지 확인. 화면은 GitHub raw에서 서빙되며 실패 시 안내 메시지 표시. 즉시 최신 반영은 `?refresh=1`.
- **예산표 반영 안 됨**: 저장소 공개 여부·`FEED_URL` 브랜치 확인. 오프라인이면 로컬값으로 폴백.
- **배지가 "미연결"**: 배포 직후 1~2초는 감지 중일 수 있음(최대 6초 폴링으로 자동 복구). 지속되면 `Code.gs` 최신본으로 재배포했는지 확인.
- **분석·보고서 클릭 시 Drive 오류**: 구버전 증상(상대경로 링크). 최신본에서 절대 URL로 해결됨 — 최신 `Code.gs` 재배포 필요.
